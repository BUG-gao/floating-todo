## 📖 这是什么

很多待办 App 太「重」：要登录、要建项目、要切窗口才能看一眼。
**悬浮待办** 反着来——它是一个**永远飘在桌面上、半透明、不打扰**的小浮窗：

- 写文档、开会、敲代码时，它静静停在角落，**一眼看到今天要做什么**；
- 不登录、不联网，**所有数据只存在你自己的电脑里**；
- 只管「今天 / 明天 / 后天」三天，**专注短期执行**，减少规划负担。

- ⌨️ **全局快捷键秒记**：在任意应用里按 `⌘⇧Space`（Windows 为 `Ctrl+Shift+Space`），浮窗立刻出现并聚焦输入框，打字回车后继续手头的事，零切换。
- ⏰ **自然语言 + 到点提醒**：输入「明天 15:00 提交方案」会自动识别到「明天」分组、设 15:00 提醒，到点弹出系统通知。
- 🔥 **每天打卡连胜**：把习惯设为「每天」常驻待办，完成后累计连续天数（streak），完成时还有撒花动效——把待办和习惯打卡缝在一起。

## ✨ 完整功能

### 待办管理
- 📅 **今天 / 明天 / 后天** 三个独立列表，互不干扰。
- ➕ 快速新增、✅ 一键完成（撒花鼓励）、🗑️ 删除；完成的事自动沉底并保留手动排序。
- 🗣️ **自然语言输入**：识别「明天 / 后天」分组、`15:00` / `下午3点半` 等时间。
- 🔔 **可选时间 + 本地通知提醒**，到点提醒你。
- ✏️ 双击标题即可编辑；更多菜单可编辑、加描述、移到其他日期、设为每天、删除。
- 📝 待办描述里的网址**自动变成可点击链接**。
- 🔁 **每天常驻待办** + 🔥 **连续打卡**：跨天不消失、每天自动重置、连胜计数。
- 🌅 **跨天自动滚动**：明天变今天、未完成顺延到今天底部。
- 🧹 一键清除已完成。

### 窗口与外观
- ⌨️ **全局快捷键**唤起并聚焦输入框；`Esc` 收起。
- 📌 始终置顶；🫧 半透明、透明度可调；🎨 自定义背景色 + 跟随系统/浅色/深色。
- 🖱️ 边缘四角拖拽缩放；缩到最小后一键放大；🔽 紧凑模式只显示今天。
- 🧭 托盘 / 菜单栏小组件，不占任务栏 / 程序坞。
- 🪟 **Windows 桌面固定**：开启后窗口进入桌面层，按 `Win+D` 显示桌面时仍然可见，但不会覆盖全屏游戏或其他普通窗口；与「始终置顶」互斥。
- 🖱️ **鼠标穿透**：开启后浮窗不再挡点击，点击落到下层窗口；可从托盘菜单随时切回来。
- 🚀 **开机自启动**（可在设置里开关）。

### 数据
- 🗒️ **全局备忘录**：一份不随日期切换的便签，自动保存。
- 💾 **导出 / 导入备份**：一键备份成 JSON，换机迁移无忧（纯本地，不上云）。
- 🗓️ **按日期保存历史**：完成、删除、跨天顺延和每天事项打卡都会写入本地 JSON，可在设置中查看历史并更改保存目录；每次更新自动保留 `.bak` 备份。

### 历史数据存储

历史功能让这个三日待办小组件也能可靠地回溯事项：记录保存在你自己选择的本地目录中，不上传、不联网。

#### 会记录什么

每条历史记录都按「事项所属日期」归档，并保留标题、描述、提醒时间、创建/完成/归档时间及状态。

| 操作或情况 | 历史状态 | 说明 |
|---|---|---|
| 勾选普通待办或每天待办 | 已完成 | 立即写入当天历史；取消勾选会撤销该条当天完成记录。 |
| 删除待办 | 已删除 | 保留删除前的内容和删除时间，避免误删后无从查找。 |
| 未完成事项跨天 | 已顺延 | 原日期会留下一条顺延记录，事项本身继续出现在今天待办中。 |
| 每天待办跨天未完成 | 未打卡 | 用于回看习惯打卡是否中断。 |

#### 使用教程

1. 点击小组件右上角的设置按钮，找到「历史记录」卡片。
2. 首次启动后，历史默认写入 `~/Documents/悬浮待办/floating-todo-history.json`。卡片会显示当前目录和记录总数。
3. 正常使用待办即可：完成、删除、跨天顺延和每天事项打卡都会自动保存，无需手动点击保存。
4. 点击「查看历史」，按日期浏览所有记录。每项都标有「已完成 / 已删除 / 已顺延 / 未打卡」状态。
5. 点击「更改目录」可选择任意本地文件夹，例如同步盘、外接磁盘或你的个人备份目录。程序会把已有历史合并复制到新位置；原位置文件会保留，不会被自动删除。

#### 备份与恢复

- 在设置中使用「导出备份」，导出的 JSON 同时包含当前待办、设置和全部历史记录。
- 在另一台设备使用「导入备份」，当前待办会恢复，历史记录会与本机历史合并；相同记录不会重复。
- 每次更新历史文件前，程序会自动保留上一版本为 `floating-todo-history.json.bak`。如果历史文件格式异常，程序会停止覆盖并在设置中显示错误，避免损坏原始数据。

#### 文件格式与位置

- 默认文件：`~/Documents/悬浮待办/floating-todo-history.json`。
- 文件为格式化后的 UTF-8 JSON，适合直接阅读、纳入备份或交给其他工具处理。
- 顶层字段包括 `schemaVersion`、`updatedAt` 和 `records`；其中每个 `records` 条目都含有稳定的 `recordId`，可用于安全去重。
- 切换历史目录只会复制并合并数据；确认新目录备份正常后，可由你自行处理旧目录文件。

## ⚠️ 重要：首次打开被系统拦截怎么办

本应用**没有购买付费签名证书**（macOS 99 美元/年、Windows 也需付费证书）。
因此首次打开时系统的安全机制会拦截。**这不是病毒，是因为没签名。** 解决方法：

### 🍎 macOS
若提示「已损坏」或「无法验证开发者」：

- **方法 A（最简单）**：在「应用程序」里找到 **悬浮待办** → **右键 → 打开** → 再点一次「打开」。
- **方法 B（提示"已损坏"时）**：终端执行（会要求输入开机密码，输入时不显示是正常的）：
  ```bash
  sudo xattr -dr com.apple.quarantine "/Applications/悬浮待办.app"
  ```
- **方法 C**：系统设置 → 隐私与安全性 → 找到被拦记录 → 点「仍要打开」。

#### 更新版本后仍提示「已损坏」
如果你已经装过旧版本，下载新版后拖到「应用程序」里覆盖安装，打开时仍提示「已损坏」，而且在「系统设置 → 隐私与安全性」里找不到「仍要打开」记录，可以这样处理：

1. 先彻底退出正在运行的旧版 **悬浮待办**。
2. 把新版拖到「应用程序」并选择覆盖。
3. 打开「终端」，执行：
   ```bash
   sudo xattr -dr com.apple.quarantine "/Applications/悬浮待办.app"
   ```
4. 回到「应用程序」，对 **悬浮待办** 右键 → 打开 → 再点一次「打开」。

> 这是因为未签名应用每次重新下载的新版本都可能重新带上 macOS 的隔离标记。更新后如果再次被拦截，重复上面的步骤即可。

### 🪟 Windows
若弹出蓝色「Windows 已保护你的电脑 / SmartScreen」窗口：点 **「更多信息」→「仍要运行」** 即可。

> 💡 同一个版本通常只需处理一次。点个 ⭐ Star 支持一下，攒够关注度后我会考虑加上正式签名，免去这些步骤 🙏

## 🛠️ 从源码构建 / 参与开发

```bash
# 前置：Node.js 18+、Rust（https://rustup.rs）
git clone https://github.com/BUG-gao/floating-todo.git

npm install
npm run dev      # 开发模式（热重载）
```

发布版安装包由 **GitHub Actions** 在打 `v*` tag 时自动构建（macOS + Windows 双平台），见 [`.github/workflows/release.yml`](.github/workflows/release.yml)。

## 🧱 技术栈与架构

- **框架**：[Tauri 2](https://tauri.app)（Rust 后端 + 系统 WebView 前端），安装包小、内存占用低。
- **前端**：原生 HTML / CSS / JavaScript，无打包步骤。
- **持久化**：当前待办与设置存于本地 `localStorage`；按日期历史存于用户可配置目录下的 JSON 文件（纯本地、不联网）。
- **插件**：全局快捷键、系统通知、开机自启、文件对话框。

```
floating-todo/
├─ src/                  # 前端（index.html / styles.css / main.js）
├─ src-tauri/            # Rust 后端、窗口/托盘/快捷键、打包配置
├─ .github/workflows/    # 跨平台自动构建
└─ legacy-macos-swift/   # 早期的 macOS 原生 Swift 版（仅存档参考）
```
